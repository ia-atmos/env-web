# Rocks of env-pico in the browser (2026-11-26)

The author on `#2` (2026-11-26): "na verdade queremos o rocks em pico.
Web teria o pico. Pergunte novamente". So the target is
`ia-atmos/env-pico` `exs/rocks/` (over `pico-sdl`, in `env-pico/c/`),
and env-web holds pico in the browser.

## Measured (env-pico b539a8c, lang main, emcc 7.0.1)

Same route as `261125-rocks-emscripten.md`: `atmos -c -e pico.atm
main.atm`, then `emcc` with the C of `pico-sdl` (`c/src/*.c`), the
runtime, the SDL2 ports (plus `-sUSE_SDL_GFX=2`), `-sASYNCIFY`, assets
preloaded. No line of `pico.atm` nor of the game changed.

`pico-sdl` needed two changes, in a local copy only
(`patches/261126-pico-sdl-emscripten.diff`):

| Where | Problem | Local change |
|---|---|---|
| `c/src/input.c:171` (`_enum`), `c/src/layer.c:279` (`aux`) | nested functions, a GCC extension; clang (emcc) refuses them | hoisted to `static` functions at file scope |
| `c/src/pico.c:86` | `SDL_Init(SDL_INIT_EVERYTHING)` fails in the browser (no haptic): assertion "SDL ERROR" | `SDL_INIT_VIDEO|AUDIO|EVENTS|TIMER` |

Then, in Chromium headless:

| Check | Result |
|---|---|
| build | 40 s; `rocks.wasm` 4.0 MB, `rocks.data` 1.6 MB |
| title, Enter, shot, moves, end of a round (1 to 0) | works |
| page during the game | 60 fps, no error in the console |
| background `imgs/bg.png` (1920x1024, RGB) | missing with the accelerated renderer (WebGL); shown with the software renderer (`PICO_TESTS` set through `ENV` in a `--pre-js`) |
