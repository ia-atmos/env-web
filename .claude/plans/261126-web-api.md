# The API of env-web: a proposal (2026-11-26)

For `#9` (the DOM by ids). Nothing decided. In the shape of `env-iup`
(`new`, `set`, `get`), with the ids of the HTML in place of handles.

## Events (the page emits them, the program awaits them)

| Event | When | Fields |
|---|---|---|
| a number | each frame (`requestAnimationFrame`): the time, as in every primary | |
| `:click [id]` | a click on an element, or inside it | `id` of the nearest element with an id |
| `:input [id, value]` | the text of a field changes (each key) | `value` |
| `:change [id, value]` | a field, a box, a choice is committed | `value` (`true`/`false` for a box) |
| `:toggle [id, open]` | a `<details>` opens or closes | `open` |
| `:key.dn [key, code]`, `:key.up [key, code]` | a key of the page | as in env-sdl and env-pico |

One listener per kind, on the document (delegation): a page needs no
registration (no `web.on`), and an element created later emits too.

## Functions

| Function | |
|---|---|
| `web.set(id, name, v)` | sets a property: `text` (the text of the element), `value`, `checked`, `open`, `disabled`, `hidden`, a `class` (`v` true or false), a `style.*` |
| `web.get(id, name)` | reads a property, as a string, a boolean, or `nil` |
| `web.new(tag, t)` | creates an element `tag` (`:button`, `:details`, ...): the named fields of `t` are its properties (`id` among them, and `parent`, the id where it goes, the body by default), and the positional ones its children (strings or elements) |
| `web.del(id)` | removes an element and its children |

## An example: the tree of threads of the old plan (`atmos-lang/web`)

```
web.new(:details, [id="t1", parent="tree", open=true,
    web.new(:summary, ["alice: Re: Freechains sync"])])

spawn {
    var n = 0
    loop {
        await 200ms
        set n += 1
        web.new(:details, [parent="t1", open=true,
            web.new(:summary, ["reply #" ++ tostring(n)])])
    }
}

loop e on :toggle [id="t1"] {
    web.set("msg", "text", e.open && "open" || "closed")
}
```

## Revision (2026-11-26)

The author: "Text e set parecem colidir". `web.text(id, s)` is
`web.set(id, "text", s)`: removed; `text` is a property of `set` and
`get`, as `value` or `open`. Four functions remain: `set`, `get`, `new`,
`del`.

## Implemented (2026-11-26, `#10a`)

`web.atm` on `main`. Differences from the proposal above, found while
writing it:
- The positional fields of `web.new` are the ids of children only (an
  id and a text are both strings: a text is the field `text`).
- An element goes into the body, or into `parent`, when created; a
  child listed by its parent moves into it (the DOM moves a node that is
  appended again). So a nested `web.new` needs no detached state.
- `:key.dn`/`:key.up` carry the `id` of the element with the focus too.
- In a native literal `$` is a variable: the dependencies of `EM_JS`
  (`$stringToNewUTF8`) are written `"\x24stringToNewUTF8"`.
